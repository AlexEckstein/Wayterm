# SFTP Sidebar

## Overview

An integrated remote file browser beside the terminal tab — drag-drop
upload/download, navigation, file operations. Like MobaXterm's SFTP
sidebar.

> **Revision note (2026-08):** the original `SftpSidebar::new` sketch
> called `.await` inside a non-async constructor and held the raw
> `SftpSession` on the GTK side. This revision uses the shared
> `SshConnection` from doc 04, a tokio-side SFTP task, and oneshot
> replies bridged to the GTK main thread. Hotkey default is now
> Ctrl+Shift+B (doc 07 de-confliction).
>
> **Revision note (2026-10, P3-1):** phase 3 implemented the SFTP core
> (`src/sftp/`) against russh-sftp 3.0. Adaptations vs. this doc:
>
> - `SftpSession::new` blocks only on the channel, but `russh-sftp`
>   3.0 needs the channel already subsystem-requested — so
>   `open_sftp_channel` lives in the connection seam (doc 04) and the
>   task converts `channel.into_stream()` in `open_session`
>   (`src/sftp/task.rs`).
> - Transfers (`Download`/`Upload`) spawn as sub-tasks with a
>   `CancellationToken` registered per `transfer_id`, and the id is
>   pre-generated by the client (`next_transfer_id()`) — the sketch's
>   inline transfer would queue `Cancel` behind the transfer.
> - Any command failure drops the cached session; the next command
>   reopens the subsystem lazily, so a closed server subsystem is
>   observable (the reply errors) and recoverable.
> - `Delete` stats the path first (`symlink_metadata` →
>   `remove_dir`/`remove_file`); OpenSSH's `sftp-server` deletes do not
>   distinguish files from directories.
> - No `ListAll` — `Cd` doubles as the listing command.
> - `format_perms`/`format_timestamp` render client-side (no new
>   chrono dependency).

## Layout

`GtkPaned`: sidebar left, terminal right, user-resizable. Sidebar =
path bar (GtkEntry) + file listing (GtkTreeView) + toolbar
([Upload][Download][Delete][Rename][Refresh][Mkdir]) + a progress bar
for active transfers. Toggle via `toggle_sftp` (Ctrl+Shift+B).

## Connection Model

The SFTP channel runs over the **existing** SSH session — no second
process, no second connection. This is the killer feature vs. KIO and
vs. shelling out to `sftp`.

The sidebar receives `Arc<SshConnection>` (doc 04's shared connection,
NOT the transport's private channel) and opens its own SFTP channel:

```rust
pub struct SftpSidebar {
    container: gtk4::Box,
    tree_view: gtk4::TreeView,
    model: gtk4::TreeStore,
    path_entry: gtk4::Entry,
    connection: Arc<SshConnection>,
    current_path: String,
    sftp_tx: mpsc::Sender<SftpCommand>,
}

pub enum SftpCommand {
    Cd { path: String, reply: oneshot::Sender<Result<Vec<DirEntry>, String>> },
    Download {
        remote_path: String, local_path: String,
        progress: mpsc::Sender<Progress>,
        reply: oneshot::Sender<Result<u64, String>>,
    },
    Upload {
        local_path: String, remote_path: String,
        progress: mpsc::Sender<Progress>,
        reply: oneshot::Sender<Result<u64, String>>,
    },
    Delete { path: String, reply: oneshot::Sender<Result<(), String>> },
    Rename { from: String, to: String, reply: oneshot::Sender<Result<(), String>> },
    Mkdir { path: String, reply: oneshot::Sender<Result<(), String>> },
    Cancel { transfer_id: u64 },
}

pub struct DirEntry {
    name: String, size: u64, modified: String,
    permissions: String, is_dir: bool,
}
```

## SFTP Task (tokio side)

One task per sidebar, spawned at sidebar creation. It owns the
`SftpSession`, creating it lazily on first command:

```rust
async fn sftp_task(
    mut rx: mpsc::Receiver<SftpCommand>,
    connection: Arc<SshConnection>,
) {
    let sftp: Option<SftpSession> = None;  // lazy — opened on first use

    while let Some(cmd) = rx.recv().await {
        // (Re)open the SFTP subsystem channel if needed:
        //   let channel = connection.open_sftp_channel().await?;
        //   channel.request_subsystem(true, "sftp").await?;
        //   let sftp = SftpSession::new(channel.into_stream()).await?;
        match cmd {
            SftpCommand::Cd { path, reply } => {
                let _ = reply.send(list_dir(&sftp, &path).await);
            }
            SftpCommand::Download { remote_path, local_path, progress, reply } => {
                let _ = reply.send(
                    download_file(&sftp, &remote_path, &local_path, &progress).await
                );
            }
            SftpCommand::Upload { local_path, remote_path, progress, reply } => {
                let _ = reply.send(
                    upload_file(&sftp, &local_path, &remote_path, &progress).await
                );
            }
            SftpCommand::Delete { path, reply } => {
                let _ = reply.send(sftp.remove(&path).await.map_err(|e| e.to_string()));
            }
            SftpCommand::Rename { from, to, reply } => {
                let _ = reply.send(sftp.rename(&from, &to).await.map_err(|e| e.to_string()));
            }
            SftpCommand::Mkdir { path, reply } => {
                let _ = reply.send(sftp.create_dir(&path).await.map_err(|e| e.to_string()));
            }
            SftpCommand::Cancel { transfer_id } => { /* cancel via CancellationToken map */ }
        }
    }
    // Task ends when the sidebar drops sftp_tx — channel close = cleanup.
}
```

Benefits of this shape:

- No `.await` in GTK code, ever. The sidebar sends a command and
  bridges the reply with `glib::MainContext::spawn_local` +
  `rx.await` inside that async closure (runs on the main loop, no
  blocking).
- The channel is bounded — if SFTP is slow, `try_send` from the UI and
  queue (same idle-flush pattern as doc 02 for keystrokes; here it
  guards against rapid navigation clicks).
- The SFTP task dying (server closed subsystem) is observable: the next
  command's oneshot reply errors → sidebar shows "SFTP session ended —
  reconnect?".

## Directory Listing

```rust
async fn list_dir(sftp: &SftpSession, path: &str) -> Result<Vec<DirEntry>, String> {
    let mut entries = sftp.read_dir(path).await.map_err(|e| e.to_string())?;
    let mut result = Vec::new();
    while let Some(entry) = entries.next().await {
        let entry = entry.map_err(|e| e.to_string())?;
        let attrs = entry.metadata();
        result.push(DirEntry {
            name: entry.file_name().to_string_lossy().into_owned(),
            size: attrs.size.unwrap_or(0),
            modified: attrs.mtime.map(format_timestamp).unwrap_or_default(),
            permissions: attrs.permissions.map(format_perms).unwrap_or_default(),
            is_dir: attrs.is_dir(),
        });
    }
    // directories first, then case-insensitive alphabetical
    result.sort_by(|a, b| b.is_dir.cmp(&a.is_dir)
        .then_with(|| a.name.to_lowercase().cmp(&b.name.to_lowercase())));
    Ok(result)
}
```

(GTK side: `model.clear()` then one `insert_with_values` per entry —
column view shows icon, name, size, modified, permissions.)

## Transfers

```rust
async fn download_file(
    sftp: &SftpSession, remote_path: &str, local_path: &str,
    progress: &mpsc::Sender<Progress>,
) -> Result<u64, String> {
    let mut remote = sftp.open(remote_path).await.map_err(|e| e.to_string())?;
    let total = remote.metadata().size.unwrap_or(0);
    let mut local = tokio::fs::File::create(local_path).await.map_err(|e| e.to_string())?;
    let mut buf = vec![0u8; 32768];
    let mut transferred = 0u64;
    loop {
        let n = remote.read(&mut buf).await.map_err(|e| e.to_string())?;
        if n == 0 { break; }
        local.write_all(&buf[..n]).await.map_err(|e| e.to_string())?;
        transferred += n as u64;
        let _ = progress.try_send(Progress { transferred, total });  // UI throttles
    }
    local.flush().await.ok();
    Ok(transferred)
}

// upload_file: mirror image (local read → sftp.create + write).
// Same buffer size, same progress reporting.
```

Progress flows to a small UI model; the progress bar updates via a glib
channel (`try_send` — drop progress events rather than block; a
stale-but-moving bar is fine, a blocked tokio task is not).

```rust
                }
            }

        }
        false

    sidebar.tree_view.add_controller(drop_target);

```

(The original sketch parsed `text/uri-list` strings with the `url`
crate — that works for older managers, but `gdk4::File` targets are
what GTK4 file managers speak now. Support both formats on the same
target. Downloads: set a `ContentProvider` on drag source — out of
scope for MVP, button-based download first.)

## Availability

SFTP sidebar exists for SSH sessions only — it needs an active
`SshConnection`. RDP/VNC/serial tabs hide the toggle; local shell
sessions could later browse `std::fs` locally (future enhancement, no
SFTP needed).

## Path Sync (nice-to-have, post-MVP)

Optional: sidebar follows the terminal's cwd. VTE emits
`current-directory-uri` when the remote shell sends OSC 7 — connect
that signal and `sidebar.cd(path)`. Nearly free, off the MVP path.
