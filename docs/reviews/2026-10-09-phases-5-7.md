# Phases 5–7 post-merge review — findings, questions, decisions

Scope: every PR merged to main for Phases 5–7 — #10/#11 (local + serial),
#12/#13 (VNC), #14/#15 (RDP), and #16 (Home tab). Branch
`agent/review-phases-5-7`. Each fix is its own commit; the commit bodies
carry the reproduction and the reasoning.

## Fixed on this branch

| Severity | Area | Finding | Commit subject |
|---|---|---|---|
| Critical | RDP | Closing an RDP tab never ended xfreerdp: the attempt's timers held the page strongly, so it was never finalized. The X window stayed drawn over the window, and the 150 ms focus poll kept handing X focus to it — **keys typed in other tabs went to the remote session**. The same applied to a tab that was merely hidden behind another. | `fix(rdp): end the session with its tab; hide it with the tab` |
| High | RDP | Legacy "Standard RDP Security" skips TLS and so skips `/cert:fingerprint:`. A peer that refuses TLS got a session **and the password** despite a pin no certificate could match (reproduced: xfreerdp3 3.32 vs `freerdp-shadow-cli3 /sec:rdp`). `/sec:rdp:off` refuses it. | `fix(rdp): refuse legacy RDP security so the certificate pin holds` |
| High | RDP | The first-contact certificate probe was fed the real password before the user had accepted the certificate. It now gets an empty one (verified: the probe still reaches TLS and prints the fingerprint). | `fix(rdp): keep the password from the probe; fail closed on store errors` |
| Medium | RDP | An unreadable trust store was treated as first contact: the user was re-prompted, and could re-pin, a host already pinned. Now it fails the connect. | (same commit) |
| Medium | RDP | The fingerprint parser matched its markers anywhere in a line and took the first hit. FreeRDP prints the server's CN *before* the real fingerprint line, so a certificate could choose the fingerprint shown in the TOFU dialog, or hide the changed-cert warning. The markers are now anchored, and all matches must agree. xfreerdp still enforced the pin; this was UI misdirection, not a bypass. | `fix(rdp): anchor the fingerprint parser and require agreement` |
| Medium | VNC | The server picks the desktop size and every pixel is filled up front: one `SetResolution(65535, 65535)` committed ~17 GB. The engine now refuses anything over 16384 per side or 64 Mi pixels. | `fix(vnc): refuse server desktop sizes beyond the framebuffer limit` |
| Medium | Local | The shell inherited every descriptor that wasn't close-on-exec, including another tab's PTY master in the window between `forkpty` and its `FD_CLOEXEC`. The child now calls `close_range(3, ~0)`. | `fix(local): close inherited descriptors before exec'ing the shell` |
| Medium | RDP | The env allowlist dropped `XAUTHORITY`, so xfreerdp couldn't open the display under GDM, SDDM or XWayland (including the Wayland relaunch path). `/audio` also lacked `XDG_RUNTIME_DIR`. | `fix(rdp): pass XAUTHORITY and XDG_RUNTIME_DIR to xfreerdp` |
| Low | RDP | Follow-up to the downgrade fix (Q1, option a): FreeRDP 2.x can't parse the argv, so it is refused at probe time with an error naming the binary, its version and what to install, instead of failing with a command-line error. | `feat(rdp): require FreeRDP 3 at probe time` |
| Low | Serial | After the device vanished, `state()` still said Connected, and a later `connect()` was refused as "already connected". | `fix(serial): report Disconnected once the reader loses the device` |
| Low | Docs | The Phase 7 plan committed the rig account's password (AGENTS.md rule 3). Redacted, but **it remains in history** — see Q2. | `docs(plans): redact the RDP rig password from the Phase 7 plan` |
| Test | RDP | `run()` holds the process lock for the whole session, so the "terminate" tests never reached `terminate()`. They passed by waiting out a 30 s sleep, and the live rig test would hang forever. | `test(rdp): make the terminate tests reach the live child` |

Refactors: `refactor(serial)` (maps the port settings once instead of
cloning the whole row), `refactor(ui)` (session-type guards that every
type now passes), `refactor(rdp)` (lends the cached probe), plus the
clean-ups listed in the RDP tab fix (no `SessionConfig` clone into the
dial, host/port computed once, the XID wait is a single counted timeout,
one X connection, the never-shown connecting view dropped). I swept every
`.clone()` in the Phase 5–7 sources. Those that remain are `Rc`/`Arc`/GObject
handles moved into `'static` closures, or owned values crossing a thread
boundary.

## Questions and decisions for you

1. ~~**FreeRDP 2.x and `/sec:rdp:off`.**~~ **Resolved: option (a).**
   The `:off` toggle syntax is FreeRDP 3 (2.x spells it `-sec-rdp`, which
   3.x rejects), so FreeRDP 2.x — the packaged `xfreerdp` on Ubuntu
   22.04, Debian 12 and RHEL 8 — is now refused at probe time, with an
   error naming the binary, its version and what to install
   (`feat(rdp): require FreeRDP 3 at probe time`). Still open:
   `/sec:rdp:off` hasn't been run on 3.15, the plan's verified version;
   its `--help` should list the toggle.
2. **Rotate or delete the `wayterm-test` rig account.** Its password is in
   commit `bf6dc7d` (PR #14) and on GitHub for good. Main isn't
   rewritten (AGENTS.md rule 6). If any service on that host accepts the
   account beyond loopback, it's a known-password login.
3. **VNC clipboard.** Server text goes straight into the system
   clipboard, even in view-only mode. A hostile or compromised VNC server
   can replace what you paste into a terminal tab ("pastejacking"). Keep
   it (TigerVNC's default), skip it in view-only, or add a per-session
   "accept server clipboard" toggle?
4. **The Phase 7 as-built docs never landed** (plan wave-close step 4).
   Doc 10 still says Phase 7 is "not started". Doc 08 §RDP still lists
   the certificate question as open and names the flag
   `/parent-window-id:` (the verified name is `/parent-window:`). I left
   them alone, because the as-built section should carry the wave-close
   verification evidence, which I don't have. Who writes it?
5. **The Phase 7 plan's argv list and the code had drifted apart before
   this review.** The plan lists `-decorations`, `/jpeg /jpeg-quality:80`,
   `/log-level:warn` and `+sound`; the code passes none of the first three
   and uses `/audio`. Which is intended?
6. **Focus while an RDP tab is visible.** The 150 ms poll moves X focus
   from the toplevel to xfreerdp whenever the toplevel has it. While an
   RDP tab is showing, GTK widgets in the same window (the session tree's
   keyboard navigation, for example) can't keep keyboard focus. The
   hidden-tab case is fixed. The visible case needs a design call:
   handing over on a click into the area, on pointer-enter, or on
   window activation, rather than polling. I need a real WM and an RDP
   server to test that.
7. **The Wayland relaunch probably races GApplication uniqueness.**
   `relaunch_under_x11` spawns a new instance, then quits. The app is
   unique (no `NON_UNIQUE`), so the new process can find the old one still
   on D-Bus, forward `activate` and exit, and then the old one quits,
   leaving no Wayterm. Code review only; the branch is untestable here.
8. **The fingerprint comes from stderr.** Anchoring plus agreement
   defeats certificate-name injection, but the fingerprint shown is still
   parsed from xfreerdp's output. Fetching the certificate in Wayterm
   (X.224 negotiation plus a rustls handshake) would remove the parsing
   entirely. xfreerdp stays the enforcement point either way. Worth it?
9. **gtk_tests under a Wayland session.** `xvfb-run -a cargo test --
   --ignored gtk_tests` fails the existing `rdp_embed_builds_and_tracks`
   on main when `WAYLAND_DISPLAY` is set: GDK picks Wayland, so there's
   no XID. Run it as `env -u WAYLAND_DISPLAY GDK_BACKEND=x11 xvfb-run -a
   cargo test -- --ignored gtk_tests`. Should the doc comment in
   `src/ui/mod.rs` say so, or should CI run the gtk_tests at all? It
   doesn't today.
10. **RDP trust is keyed by the host as typed.** `RDP.example.com`,
    `rdp.example.com` and the IP are separate pins. That means a
    re-prompt, not a bypass. Normalize?
11. **IPv6 RDP hosts.** `/v:<host>:<port>` with a bare literal (`::1`) is
    ambiguous; FreeRDP expects `[::1]:3389`. `build_args` doesn't add
    brackets.
12. **The status bar says "Connecting…" for 15 s.** `Connected` is
    "alive 15 s with no ERRCONNECT", even when the desktop showed up
    after one second. Discovery already knows when xfreerdp maps its
    window, which would be a better signal.
13. **Smaller items:** the VNC size cap values (16384 per side, 64 Mi px)
    are a judgment call. `ErrorRing` keeps 200 stderr lines of unbounded
    length. `cached_probe()` blocks the GTK thread once, on the first RDP
    tab. vnc-rs sizes some allocations from server fields (e.g.
    ServerCutText); that's upstream. A lock-free terminator handle on
    `RdpProcess` would be cleaner than the documented abort-then-terminate
    contract.

## Verification

- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and
  `cargo test` all pass. So do the gtk_tests, under
  `env -u WAYLAND_DISPLAY GDK_BACKEND=x11 xvfb-run -a` (see Q9), and the
  docs link check.
- **Mutation checks.** Each of these went red with its fix removed: the
  focus gate, the child unmap, the shell's descriptor close, and the
  serial state on loss.
- **Live FreeRDP 3.32 on this host,** using a throwaway self-signed cert
  and loopback or Unix-socket servers only:
  - `sfreerdp-server3`, through the real `RdpProcess`: the empty-password
    probe printed the fingerprint and exited in ~0.1 s, a wrong pin was
    refused in ~0.1 s with the fingerprint parseable, and the right pin
    connected and terminated cleanly.
  - `freerdp-shadow-cli3 /sec:rdp` under Xvfb: the downgrade connects
    without `/sec:rdp:off` and is refused with it.
  - Nothing was written to `~/.config/freerdp`.
- **Not verified:** a GUI session against xrdp or Windows, the Wayland
  branch, FreeRDP 3.15 or 2.x, and real serial hardware.
- **One finding withdrawn during the review.** I first read xfreerdp's
  exit code 143 as a timeout kill and concluded that 3.32 hangs on its
  certificate prompt. It is FreeRDP's own `XF_EXIT_TLS_CONNECT_FAILED`.
  The change built on that misreading was removed before anything was
  pushed.
