# Phase 7 — RDP tabs

Status: starting · 2026-10-09 · Orchestrator: Hermes (manager profile) ·
Fleet: OpenCode CLI one-shot lanes (standing policy; Phase 6 precedent).

## Goal

An RDP session opens as a notebook tab like SSH/local/serial: the remote
desktop renders embedded in the window (X11/XWayland), keyboard and pointer
input reach the server, the password feeds xfreerdp over stdin (never argv,
env, logs, or disk), the certificate policy is enforceable (a changed cert
is refused like a changed SSH host key), and state flows through the same
status/resilience machinery as the other tab types.

## Design decisions (orchestrator, settled 2026-10-09 — do not relitigate)

**1. Approach: xfreerdp subprocess + X11 reparenting (doc 08 Path A)**
VALIDATED by orchestrator spike this session. Evidence (all on this host,
FreeRDP 3.15.0, xrdp 0.10.1 on 127.0.0.1):

- A gtk4 DrawingArea's native surface gives a real X window;
  `gdk4-x11::X11Surface::xid()` works. Spike window XIDs `0x200004` etc.
- `xfreerdp3 /parent-window:<xid>` re-parents ONE client window under the
  host window; `x11rb` `query_tree` finds it; `configure_window` moves it
  to 0,0+size; live outer-window resize (900×640→1100×750) propagated to
  the child automatically. Screenshot proof: the `wayterm-test@hermes`
  shell rendered inside the embedded area (`/tmp/rdp-rig/spike-shot2.png`).
- Input: keystrokes/clicks traverse the embedded window into the remote
  session — server-side proof file `/tmp/rdp-input-proof` contained `42`
  after typing echo `$((6*7))` through the app (PointerRoot path, and the
  WM path after the activation handoff below).
- Fragility findings (must be modeled by P7-1/P7-2, see lanes):
  a. Under a WM the pressed key/click **lands in the child** (GTK never
     sees it) — focus handoff must hook window **activation**
     (`get_input_focus()`/active-window) → `SetInputFocus(PARENT, child)`.
     Without it, no keyboard (verified NO-PROOF before the fix).
  b. A killed xfreerdp may leave an orphan child under the parent — the
     tab tracks ITS OWN subprocess (pid → X id at spawn) and configures/
     kills only that one; never "any child".
  c. The child spawns at −1,−1 — configure x=0,y=0 explicitly.
  d. Closing a tab must TERM the tracked xfreerdp and close stdin.
- Therefore: v1 ships embedded; libfreerdp stays a future item.

**2. Certificate policy — Wayterm's own trust store + fingerprint
pass-through, never `/cert:ignore`.** Verified matrix on FreeRDP 3.15 vs
xrdp (ports 3391 = rig A cert, 3392 = rig B, homes swapped clean):

| probe | result |
|---|---|
| `/cert:tofu`, fresh home, first connect | connects; writes `~/.config/freerdp/server/<host>_<port>.pem` |
| `/cert:tofu`, SAME host:port, changed cert | **REFUSED** `ERRCONNECT_TLS_CONNECT_FAILED`, `NEW HOST IDENTIFICATION!` |
| `/cert:fingerprint:sha256:<correct>`, fresh home | connects (CN-mismatch fine) — and FreeRDP writes **no** known-store file |
| `/cert:fingerprint:sha256:<wrong>` | **REFUSED** |

So: per-session trust state in Wayterm (new `rdp_trust` table: host, port,
fingerprint sha256, first_seen) with the SSH host-key UX (prompt on
unknown + changed-key warning dialog); the stored fingerprint is passed as
`/cert:fingerprint:sha256:<hex>` and FreeRDP's own store stays untouched
(fingerprints mode writes nothing — verified). A changed cert is refused
client-side by xfreerdp; Wayterm's prompt flow then decides. This
implements the doc-08 open question WITHOUT the MITM hole. (Doc 08's
"silently rejects under tofu" spike conclusion is stale for 3.15 — probably
observed with a pre-populated known-store; superseded by this matrix.)

**3. FreeRDP version: probe `xfreerdp3` then `xfreerdp`; warn below 3.20.**
Doc 08 flagged `/from-stdin` bugs in 3.5–3.17 (fixed 3.20+) and says
"require ≥ 3.20 **or test on each target**". This target (3.15) is tested
END TO END this session on the full path (`/from-stdin:force` + `/u` + cert
modes + reparenting). v1: runtime probe reports the version; below 3.20 →
status-bar warning "FreeRDP <3.20 — from-stdin known-buggy band, verify if
stdin auth fails" but connect proceeds. The probe result rides the tab
state. Binary names probed in order (doc 08 name table).

**4. argv/stdin contract** (from doc 08 + verified this session):
`/parent-window:<xid>` `/v:<host>:<port>` `/u:<user>` `/w:` `/h:`
`/bpp:<depth or 32>` `/cert:fingerprint:sha256:<fp>` `/from-stdin:force`
`+clipboard -decorations +fonts /jpeg /jpeg-quality:80` (audio per
`rdp_options.audio` default off: `+sound` only when enabled),
`/log-level:warn` (stderr → the engine's ring buffer for the error view
only). NEVER `/cert:ignore`, NEVER `/p:`. Username on argv (not secret);
password = single line on stdin, pipe held open until the session is up.

## Lanes (disjoint by file ownership)

### P7-1 — RDP engine core: `agent/phase7-rdp-engine`

Owns: `src/rdp/` (new: `mod.rs`, `cert.rs`, `process.rs`, unit tests),
`Cargo.toml`+`Cargo.lock` (adds nothing heavy: x11rb = used by P7-2; only
add crates this lane actually uses), `src/lib.rs` (one line
`pub mod rdp;`), `src/store/db.rs` + `src/store/model.rs` ONLY for the
`rdp_trust` table migration + accessor fns (+ tests), `src/ui/tab.rs` NOT
touched by this lane.

Delivers:

1. **`cert.rs`** — trust resolver: `load_trust(host, port)` →
   `Option<fingerprint>`; `record_trust(host, port, fp)`; logic fn
   `cert_fingerprint_to_arg(policy, stored, fp_seen)` returning
   `Option<String>` for the argv (unknown → None means "caller prompts;
   on user-accept record then pass fingerprint"; changed → None + change
   event; same → Some(arg)). Unit-test every branch (unknown/same/changed/
   disabled-by-policy-note).
2. **`process.rs`** — `RdpProcess` (display-free): builder carries
   host/port/username/geometry/depth/options/cert-arg; spawns the binary
   (probe `xfreerdp3` then `xfreerdp`), argv exactly per the contract
   above; feeds the password line to stdin and keeps the pipe open
   (Zeroizing bytes in, dropped after feed); pumps stderr into a
   bounded ring (for error views, never logs); monitors exit (pid status
   → `Ended(exit)` event on an mpsc); `terminate()` kills the tracked pid
   (and, if it spawned, its pgroup); version probe fn
   (`xfreerdp* --version` parse → `(name, version)`). argv builder is a
   PURE fn `build_args(...) -> Vec<String>` with unit tests asserting no
   password ever appears; argv order/flags pinned by test.
3. **Store migration** — `rdp_trust(host TEXT, port INTEGER, fingerprint
   TEXT NOT NULL, first_seen INTEGER, PRIMARY KEY(host, port))`;
   migration numbered after the newest existing; accessor fns + tests
   (mirroring existing table tests).
4. **Doc comments carrying the as-built facts**: stdin-order trap,
   pipe-must-stay-open, the 3.5–3.17 caveat, cert matrix summary.

Rules: wire-or-delete (any unused item is consumed here or deleted, no
`#[allow]` walls); gates bare; report gate output; mutation check on the
argv builder test (break the builder, show a test red).

Verify: `cargo test` green with the pure suites.

### P7-2 — Embedding + RdpTab UI: `agent/phase7-rdp-ui`

Depends on P7-1 (rebases on the wave tip after P7-1 lands). Owns:
`src/ui/rdp_tab.rs` (new main surface), `src/ui/mod.rs` (one line),
minimal enumerated touches to `src/ui/tab.rs`, `Cargo.toml` (adds
`x11rb = "0.13"` + `gdk4-x11 = "0.11"`), `tests/rdp_tab_flow.rs`
(display-free), `src/ui/rdp_tab.rs gtk_tests` (xvfb, `#[ignore]`-style
like session_dialog tests).

`src/ui/tab.rs` touches EXACTLY: (a) `SessionTab::open`/`start_connect`
adds the RDP dispatch arm → `rdp_tab::start(notebook, page, session, gen)`
(mirroring the VNC arm — flag it per AGENTS.md in the commit body);
(b) marks the VNC-arm helper set used by rdp_tab `pub(crate)` (same
list as VNC used); nothing else. Any additional need = flag in the
report, don't improvise.

Delivers:

1. **Embedding** (`src/ui/rdp_tab.rs`): the page hosts an X11-backed
   area; on map, take `X11Surface::xid()`; spawn `RdpProcess` with that
   xid (tokio spawn_blocking for the spawn+stdin-feed part; the GTK side
   holds the weak refs); an x11rb connection on the main thread performs:
   - child discovery scoped to OUR subprocess (spike finding (b)) —
     `query_tree` filtered by the child window's `_NET_WM_PID` or spawn-
     time query; configure x=0,y=0 w×h on every size-allocate signal
     (not poll-only; poll fallback every 500 ms),
   - focus handoff on window activation (GDK `is-active`/active-window
     notification → `SetInputFocus(PARENT, our_child)`; also on realize),
   - on tab close/retry: `terminate()` the process; unmap removes focus.
2. **Cert flow at connect**: `cert::load_trust`; if none → run the
   hostkey-dialog in its RDP-cert wording ("Connect and store
   certificate fingerprint?" + show fp sha256) — resolve BEFORE spawn
   (TOFU prompt); changed → warn dialog (accept: update the store;
   refuse → connect aborted, status Error "server cert changed"). The
   fingerprint arg only ever comes from OUR store (P7-1 resolver).
3. **Password** through the credential chain (`rdp_password`,
   `credential_manager(session.name)`; blocked-prompt pattern like the
   VNC arm). Password bytes go to `RdpProcess` stdin ONLY.
4. **Status/state**: same TransportEvent-shaped flow as VNC (Connecting
   on spawn, Connected when xfreerdp first renders — approximate with a
   spawn-success + first-configure signal, `Log` notes), Ended →
   error view + retry flows exactly like the other types (retry reuses
   the RDP arm); no SFTP sidebar; no Tier-2 shortcut controller (doc 08
   §Tabs); status bar shows host:port + state.
5. **Version check**: on spawn, run the probe; `<3.20` → status-bar
   warning once per tab (P7-1's probe fn).
6. **Wayland path**: if the GDK surface is not X11 → the doc 08 choice
   dialog (relaunch `GDK_BACKEND=x11` / open un-embedded). Smoke-tested
   under X11 here; declared gap: the Wayland branch is untestable on
   this host (code-reviewed only).
7. **gtk_tests** (xvfb): construct the tab against the live rig;
   assert: XID extraction works, a child window exists under the host
   after spawn, configure-on-resize moves it (query, resize outer,
   re-query), focus handoff sets X focus (GetInputFocus == child),
   terminate kills the tracked pid, no GLib criticals.
8. **tests/rdp_tab_flow.rs** (display-free): argv assembly from session
   config (per options: audio/clipboard/fonts/printer + geometry),
   cert-arg policy mapping, status text mapping, version-warning
   threshold, state text.

Verify (doc 10): end-to-end — an RDP session from the tree shows a live
interactive desktop in the tab (wave close, below).
