# Phase 6 — VNC tabs

Status: starting · 2026-10-09 · Orchestrator: Hermes (manager profile) ·
Fleet: Claude Code CLI via herdr panes, sonnet (Phase 5 precedent).

## Goal

A VNC session opens as a notebook tab like SSH/local/serial: the remote
framebuffer renders in a Cairo-backed DrawingArea, keyboard and pointer
input reach the server, the password is resolved through the credential
chain (never logged, argv, or disk), and state flows through the same
status/resilience machinery as the other tab types.

## Design decision — Path B (doc 08 §VNC)

Doc 08 Path B's condition ("a pure-Rust client if it matures by Phase 6")
is met:

- **pinned crate: `vnc-rs = "0.6"`** (lib name `vnc`), 0.6.0 released
  2026-09-21, 2.15M downloads, MIT/Apache-2.0, tokio-native — matches doc
  04's threading model (engine on tokio, views on GTK, channels across).
- Verified API surface (docs.rs 0.6.0 + repo example, re-verify against
  the registry source before implementing — pin-drift rule):
  - `VncConnector::new(TcpStream)` → `.set_auth_method(closure → Ok(String))`
    → `.add_encoding(VncEncoding::{Tight, Zrle, CopyRect, Raw})`
    (plus `DesktopSizePseudo`, `CursorPseudo`) → `.allow_shared(true)`
    → `.set_pixel_format(PixelFormat::bgra())` → `.build()?`
    → `.try_start().await?` → `.finish()?`
  - `client.poll_event().await → Result<Option<VncEvent>>`;
    `client.input(X11Event).await`; `client.close().await`.
  - Server→client: `VncEvent::{SetResolution(Screen{w,h}), RawImage(Rect,
    Vec<u8>), Copy(dst,src), SetCursor, Bell, Text(String), Error(String),
    DesktopUpdate(..), SetPixelFormat(..)}` (`#[non_exhaustive]`).
  - Client→server: `X11Event::{Refresh, FullRefresh, KeyEvent(
    ClientKeyEvent{keycode: u32 (X11 keysym), down: bool}),
    PointerEvent(ClientMouseEvent{position_x, position_y, bottons: u8}),
    CopyText(String)}`.
  - Pointer button bits: 1 left, 2 middle, 4 right, 8 scroll-up,
    16 scroll-down.
  - README: Tight/ZRLE/Raw/CopyRect decode proven by the author; TRLE
    decode present but untested upstream; negotiated resize via
    ExtendedDesktopSizePseudo (`resize_desktop`, `DesktopUpdate` events).
- **Framebuffer is plain pixels, not a cairo surface:** the engine task is
  display-free — it owns `Mutex<VncPixels>` (BGRA32 `Vec<u32>` + dims) and
  the GTK side blits pixels→`ImageSurface` in its draw handler. cairo-rs
  surface types are not Send; keeping them out of the engine respects the
  GTK/tokio boundary (doc 04) and keeps `src/vnc/` unit-testable.
- Transport trait untouched: `create_transport` keeps erroring for VNC
  ("RDP/VNC don't use byte-stream transport"), and `SessionTab::open`
  routes VNC into its own flow before any factory call. No seam changes;
  nothing escalates.

### v1 gaps (declared, mirroring Phase 4/5 style)

- `vnc_options.quality` (0–9) is stored but not passed to the encoder
  unless the crate API exposes a quality knob — lane verifies; otherwise
  declared a gap, field stays stored.
- `vnc_color_depth` is stored, not applied: the client always requests
  BGRA32 (format is client-chosen in RFB; deep-color path is a follow-up).
- Clipboard is receive-only (server Text → GTK clipboard). Local→server
  copy (`CopyText`) is possible in the crate but out of v1 scope.
- Bell is logged, not audible.
- VeNCrypt/TLS: doc 08 defers to post-v1; plain VNC over SSH tunnels.

## Lanes (disjoint by file ownership)

### P6-1 — VNC engine core: `agent/phase6-vnc-core`

Owns: `src/vnc/` (new: `mod.rs`, `client.rs`, `framebuffer.rs`, tests),
`Cargo.toml`+`Cargo.lock` (adds `vnc-rs = "0.6"`), `src/lib.rs` (one line:
`pub mod vnc;`), `tests/common/vnc.rs` (new — shared RFB mock server),
`tests/vnc_wire.rs` (new), `tests/vnc_live.rs` (new, skip-guarded).

Delivers:

1. **`framebuffer.rs` — `VncPixels`** (Send-safe, display-free):
   `width/height` + `Vec<u32>` BGRA32 (client-requested
   `PixelFormat::bgra()` byte order). API: `new(w, h)`, `resize(w, h)`
   (preserves overlapping pixels), `write_rect(Rect, &[u8])` (clamps rects
   that overrun the dims — a lying server must not panic or corrupt
   neighbors), `copy(dst, src)` (clamped, overlap-safe), `snapshot()` for
   the blit. Unit tests for every clamp/copy/resize edge.
2. **`client.rs` — `VncSession`**: `connect(host, port, password:
   Zeroizing<u8/_v>, encodings, shared) -> VncSession` wrapping the vnc-rs
   client; `spawn_engine` that runs the select loop:
   - periodic `Refresh` (start ~30 ms cadence; the example sends Refresh
     every 16 ms — VERIFY from the crate source whether handshake already
     requests updates; adjust cadence and record findings),
   - drains the input channel (`std`-side `X11Event`s),
   - maps `poll_event` results into: framebuffer writes (RawImage /
     SetCursor pixels), Copy, SetResolution → resize + `Resolved(w, h)`
     event, Bell/Text/Error → surfaced events,
   - on cancel or fatal error: `close()` the client, emit `Ended(reason)`.
   Public events to the UI: `mpsc<VncUiEvent { Dirtied, Resolved(w, h),
   Bell, Clipboard(String), Ended(String)> }`; input: `mpsc<X11Event>`.
3. **`tests/common/vnc.rs` — a real RFB mock server** (TcpListener,
   hand-rolled): RFB 003.008 both handshake variants, security `None` and
   VNC auth (DES challenge/response per RFC 6143 §7.5.2 using
   `des` crate), server framebuffer updates (Raw + CopyRect +
   DesktopSizePseudo), reads and records client pointer/key events, and a
   configurable failure mode (bad bytes, wrong-password response, early
   drop). This is real wire verification of OUR client, deterministic in
   CI, and the mutation-check bed.
4. **`tests/vnc_wire.rs`**: handshake+auth round trip (both security
   paths), password mismatch → clean auth failure, framebuffer update
   decode lands correct pixel values in VncPixels, Copy handled, Desktop
   resize observed, pointer/keysym events reach the mock server intact,
   wrong bytes → `Ended` without hang, server drop → `Ended`.
5. **`tests/vnc_live.rs`**: skip-guarded on `VNC_TEST_HOST/PORT/PASSWORD`
  env (print the skip reason — existing sshd convention); connects to a
  real server and asserts a framebuffer update within a few seconds.
6. Engine cadence + semantics findings recorded in `src/vnc/client.rs` doc
   comments (crate doc is 33% — the code comments carry what we learned).

Rules: wire-or-delete (any unused item is deleted, no `#[allow]` walls);
gates bare (`cargo fmt --check`, `cargo clippy --all-targets -- -D
warnings`, `cargo test`, `cargo build`); report gate output. Mutation
check required: deliberately corrupt one decoder/writer and show the test
goes red (say which test).

Verify (doc 10): the wire protocol path is proven — real client, real
protocol bytes.

### P6-2 — VncTab UI wiring: `agent/phase6-vnc-ui`

Depends on P6-1 (branches from the wave tip after P6-1 lands). Owns:
`src/ui/vnc_tab.rs` (new, main surface), `src/ui/mod.rs` (one line),
minimal touches to `src/ui/tab.rs` (enumerated below), unit tests near the
consumers, `src/ui/vnc_tab.rs` `gtk_tests` (xvfb-run, `#[ignore]`
pattern like session_dialog's), `tests/vnc_tab_flow.rs` (display-free
state-mapping tests).

`src/ui/tab.rs` touches are EXACTLY: (a) `SessionTab::open` adds VNC to
the auto-connect dispatch routing to `vnc_tab::VncTab::open` (a match arm
change, mirroring the Phase 5 serial arm — flag it per AGENTS.md);
(b) the status/`error_view` helpers used by vnc_tab marked `pub(crate)`;
nothing else. Any additional need = flag in the report, don't improvise.

Delivers:

1. **Tab page** (`VncTab::open(notebook, session)`): builds the page with
   an expanding `gtk4::DrawingArea`; tab label like the terminal tabs
   (reuse `tab_label`); VNC tabs attach NO Tier-2 shortcut controller (doc
   08 §Tabs — remote desktop keeps its keys; only global accels
   intercept).
2. **Password resolution** before the engine starts: same
   `credential_manager(session.name).lookup(id, "vnc_password")` chain;
   prompt runs via the existing auth-dialog responder (blocks the dial,
   same as the SSH dial's blocking-pool pattern); `None` = user cancelled
   → `Disconnected` status, no error dialog spam.
3. **Engine wiring**: P6-1 `VncSession` + engine over a `TcpStream`; on
   `Ended` → show_error_view + retry flows exactly like the other types
   (retry uses start_connect's per-type VNC arm); on `Dirtied` →
   `queue_draw`; `Resolved` → resize surface + `queue_resize` request.
4. **Draw handler**: blit `VncPixels` → `cairo::ImageSurface::create_for_
   data` (BGRA, stride = w*4) → scale matrix when `scaling` (default true)
   to fit the widget, else 1:1 centered; paint.
5. **Input**: `EventControllerKey` (forward press/release keyvals as
   X11 keysym — GDK keyvals ARE keysyms, doc 08) with modifiers arriving
   as their own events; `EventControllerMotion` + `GestureClick` +
   scroll → pointer button bits; widget scale factor maps widget
   coordinates → framebuffer coordinates; ALL input gated off in
   view_only mode.
6. **State events**: the same `TransportEvent`-shaped state flow the
   serial tab uses (StateChanged Connecting/Connected/Error,
   ConnectionLost on Ended) → status bar + tray + confirm-close parity;
   status bar shows `host:port` + state (serial's pattern, no SFTP
   sidebar for VNC — assert in the flow test).
7. **gtk_tests** (xvfb): construct VncTab against the mock RFB server
   pattern's event stream — assert controllers exist and route to the
   input channel (spy), draw blits pixels (compare via reading back a
   surface round-trip), view_only blocks input, no GLib criticals.

`tests/vnc_tab_flow.rs` (display-free): the state-mapping fns (status
text, view-only gating, coordinate mapping) — pure-function tests.

Verify (doc 10): end-to-end — a VNC session opens from the tree into a
live framebuffer (final interactive verify at wave close, below).
